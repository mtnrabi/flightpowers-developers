# Amadeus Self-Service alternatives: which ones you can actually get access to

Most "Amadeus alternatives" lists compare features. That is not the problem you have.
If you built on Amadeus Self-Service, you were a solo developer or a small team, and
what you need to know about each replacement is one thing: **can you get a key today,
or does someone have to approve you first?**

So that is the column this page leads with. Every gate below is quoted from the
provider's own live page with the URL and the date I read it. Where I could not read
the page from my machine, I say so instead of filling the cell.

Disclosure up front: I run FlightPowers, which is the last row in the table. Read that
row as a vendor describing his own product, and check the rest yourself.

## First, the state of Amadeus Self-Service

I am not going to assert a shutdown date, because I could not find one on an Amadeus
page. Here is what I can observe from my own machine, re-run on **2026-09-04**:

```bash
getent hosts test.api.amadeus.com
# (no output, no record)

getent hosts api.amadeus.com
# (no output, no record)

curl -sS -m 15 https://test.api.amadeus.com/v1/security/oauth2/token
# curl: (6) Could not resolve host: test.api.amadeus.com

curl -sS -o /dev/null -w "%{http_code} -> %{redirect_url}\n" \
  https://developers.amadeus.com/self-service
# 301 -> https://developers.amadeus.com/

gh api "orgs/amadeus4dev/repos?per_page=100" \
  --jq '"archived \([.[]|select(.archived)]|length) of \(length)"'
# archived 20 of 20
```

**Both API hostnames have no A record.** That matters more than the portal redirect,
because a missing DNS record is not a paused account or an expired token. There is
nothing at the address to authenticate against. The `amadeus4dev/developer-guides`
README opens with "The Amadeus for Developers Self-Service offer has been deprecated."

Amadeus Enterprise is untouched and still a serious platform. If you hold IATA or ARC
accreditation, or work through a consolidator, that is your path and nothing here
argues otherwise. This page is for everyone Enterprise was never designed to serve.

### A note on what these rows are not

This is a table about access, not about quality. SerpApi, SearchApi.io and Scrapingdog
return Google Flights data the same way we do, and they are self-serve the same way we
are, so if the only thing you need is a key today, they are real answers and the
comparison moves to price and to what each response contains.

Duffel is not a worse choice than us. It is a different product. If you sell tickets,
you need Duffel or Enterprise, and no amount of price data substitutes for that. What
the search ratio tells you is that Duffel is priced for a product that books, so a
monitoring workload is the wrong shape for it.

## Why the gate is the column that matters

Feature tables make these look interchangeable. They are not, and the reason has
nothing to do with features.

Amadeus Self-Service existed because someone at Amadeus decided a developer with a
side project should be able to get a sandbox key without talking to anyone. When it
went away, most of what remained had an approval step in front of it, and the approval
step is usually calibrated for a company, not a person. An audience review assumes you
already have an audience. A monthly-visitor minimum assumes you already have traffic.
Seller verification assumes you are selling something.

If you are rebuilding a fare alert, a price calendar, a research notebook or an AI
agent, you have none of those yet, and you cannot get them without the data. That is
the loop this page exists to break.

## Migrate from Amadeus in 10 minutes

This is the shopping half of Self-Service: `Flight Offers Search` and `Hotel Search`.
It does not cover `Flight Create Orders`. Nothing here issues a ticket.

### 1. Get a key (about a minute)

Subscribe to the free BASIC tier on RapidAPI. There is no application form and no
approval step: the key is live on the page as soon as you subscribe.

- Flights: [Google Flights Live API](https://rapidapi.com/mtnrabi/api/google-flights-live-api)
- Hotels: [Booking Live API](https://rapidapi.com/mtnrabi/api/booking-live-api)

### 2. Delete the OAuth code (about two minutes)

Amadeus used OAuth2 client credentials. Fetch a token, cache it, watch it expire,
refresh it. Replace all of that with one header:

```bash
# Before
POST https://test.api.amadeus.com/v1/security/oauth2/token
# -> { "access_token": "...", "expires_in": 1799 }

# After: no token endpoint. One header on every request.
x-api-key: YOUR_RAPIDAPI_KEY
```

Confirm the key works with `GET /v1/verify` before you run a real search.

### 3. Rename the fields (about five minutes)

| Amadeus Flight Offers Search | FlightPowers |
| --- | --- |
| `originLocationCode` | `from_airport` |
| `destinationLocationCode` | `to_airport` |
| `departureDate` | `departure_date` |
| `returnDate` | `return_date`, on `/v1/flights/roundtrip` |
| `adults` | `passengers`, a list: `1` adult, `2` child, `3` infant on lap, `4` infant in seat. Two adults is `[1, 1]` |
| `includedAirlineCodes` | `airline_codes` |
| `excludedAirlineCodes` | `exclude_airline_codes` |
| `nonStop=true` | `max_stops: 0` |
| `max` | `limit` |
| `currencyCode` | `currency` |
| `maxPrice` | `max_price` |
| `travelClass` | `seat_type`, and only `1` Economy and `3` Business exist |

The full mapping, including hotels, is on the
[Amadeus comparison page](/compare/amadeus).

### 4. Run it

Here is a real run, JFK to LHR on 2026-11-12, made against `api.flightpowers.com` at
**12:18 UTC on 2026-09-04** and pasted unedited. It took 8.4 seconds and returned five
itineraries. The prices were live at capture time and have moved since, which is the
whole point.

```bash
curl -X POST https://api.flightpowers.com/v1/flights/oneway \
  -H "x-api-key: $FLIGHTPOWERS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "from_airport": "JFK",
    "to_airport": "LHR",
    "departure_date": "2026-11-12"
  }'
```

Response headers:

```
x-search-status: ok
x-search-results: 5
x-search-attempts: 1
x-search-combinations: 1
```

First of the five results:

```json
{
  "price_range_in_relation_to_other_periods": "high",
  "price_insights_low": 170,
  "price_insights_high": 285,
  "from_airport": "New York (JFK)",
  "to_airport": "London (LHR)",
  "departure_date": "2026-11-12",
  "price": "$295",
  "price_as_number": 295,
  "duration": "7 hr 10 min",
  "duration_seconds": 25800,
  "airline": "Virgin Atlantic | Air France, Delta, KLM",
  "stops": 0,
  "stops_info": [],
  "departure_description": "8:00 AM on Thu, Nov 12",
  "arrival_description": "8:10 PM on Thu, Nov 12",
  "buy_link": "https://www.google.com/travel/flights?tfs=..."
}
```

### 5. Read the three fields Amadeus never gave you

Look at the top of that response. $295 sits above a historical band of $170 to $285,
so Google calls it `high`. That is a fare-watch trigger you can write on day one,
without building a price history database first.

- `price_range_in_relation_to_other_periods`: `"low"`, `"typical"`, `"high"`, or `null`
- `price_insights_low` / `price_insights_high`: the band behind that verdict
- `x-search-status`: separates "Google has no itineraries" from "the search did not
  finish". Amadeus returned an empty array for both, and so does almost everything
  else on this page

The band is `null` when Google shows none. Handle that case.
[How the verdict works](/flights-api/price-insights) ·
[How search status works](/flights-api/search-status)

coverage differs in both directions, and neither dataset is a superset of the other.
Run your three hardest routes on both and compare against your Amadeus logs.

## What none of this replaces

If your product completes the purchase, you need a booking platform, not a data API.
Nothing here issues tickets, creates PNRs, or confirms reservations.

- **Flight Create Orders, Hotel Booking API, order management, seat maps, ancillaries.**
  Go to Amadeus Enterprise, or to a booking platform such as
  [Duffel](/compare/duffel).
- **NDC content, private fares, consolidator content.** Amadeus Enterprise.
- **Multi-city and open-jaw itineraries.** We do one-way and round-trip only.
- **Reference data**: airports, airlines, cities, points of interest, transfers,
  activities. Not part of the product.

What we do replace is the shopping half: `Flight Offers Search` becomes
`POST /v1/flights/oneway` or `/roundtrip`, and `Hotel List` plus `Hotel Search`
collapse into `POST /v1/hotels/search` with a free-text `destination`, so the ID
resolution step disappears.

## Questions

**Is Amadeus Self-Service shut down?**
I will not assert a date, because there is no Amadeus page stating one that I could
find. What I can verify myself, on 2026-09-04: `test.api.amadeus.com` and
`api.amadeus.com` have no DNS record, `/self-service` 301s to the homepage, and all 20
`amadeus4dev` repositories are archived with a deprecation notice in the README. The
commands are at the top of this page.

**Which alternatives can I actually sign up for today, with no approval?**
From the table above: FlightPowers and SerpApi are self-serve. Duffel gives you a
sandbox immediately but gates production behind verification. Kiwi, Skyscanner and
Travelpayouts each require someone to approve you first.

**Is there a flight price API with no approval process?**
Yes. A RapidAPI listing is self-serve by construction: you subscribe, the key appears,
you call it. That is what FlightPowers is, and it is what SerpApi's Google Flights
endpoint is too. The trade is that neither returns GDS content or lets you issue a
ticket.

**Can I book flights with FlightPowers?**
No. It is a data API. Every result carries a `buy_link` into Google Flights, and every
hotel result a link into Booking.com, but the purchase happens there. If your product
issues tickets, use Duffel or Amadeus Enterprise.

**Should I move to Amadeus Enterprise instead?**
If you are an accredited travel business and you need booking and ticketing, yes.
If you chose Self-Service precisely because it was self-serve, Enterprise is not a
smaller version of the same thing.

**Is the data the same as what Amadeus served?**
No. Amadeus served GDS-sourced content. This is live Google Flights consumer pricing
and live Booking.com rates. Google Flights includes low-cost carriers with no GDS
presence, and GDS carries fares Google never shows. Run your own routes on both.

**How does authentication change?**
Amadeus used OAuth2 tokens that expired inside half an hour. Here it is one static
`x-api-key` header. Delete the refresh code and its cache.

**What about hotels?**
Same split. Live Booking.com rates for search and comparison, including
[per-country pricing](/hotels-api/geo-pricing). For a confirmed reservation, a booking
platform.
